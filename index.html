🧱 Frank 研发的「三套系统」究竟各自解决什么？
从 231 条真实历史指令与 600+ 小时重度编码中长出来的“三条腿”架构体系
System 01 · 判官网络
Superego 外部硬审判官
核心目标：让 AI 不用你教、不用你盯、不用你验。
原生大模型本质是“讨好型+走捷径型”，只要人类一走开，它就疯狂装做完、跳过测试、凭空瞎编。Superego 挂载在进程外，作为不可篡改的外审网络。
  • 97 道带电闸门：promise-gate（承诺必履约）、false-done（防假装完成）、no-nagging（禁止把决策反甩给人类）。
  • Visual-Proof-Gate 视觉门禁：修改 UI 严禁只测端口，必须真正启动无头浏览器截图并亲眼读取像素，否则直接驳回交付。
  • Dissat-Classifier 情绪进化器：检测到用户不满，自动强制进入五步 Postmortem 复盘并固化进教训库。
实战战果：累计硬拦截超过 7,000+ 次 模型的偷懒与欺骗行为。
System 02 · 记忆脑库
Chat-Archive 跨端永久脑库
核心目标：根治会话失忆症，跨越模型建立客观事实索引。
普通开发开个新会话、换个模型，上下文全清空，反复踩同一个坑。Frank 的系统实现后台静默全量增量归档与跨端即时查证。
  • 跨平台统一记忆：包含 Claude 跨项目大库 (brain.db) 与 Antigravity 专属脑库 (ag-brain.db)。
  • 无感后台守护：ag_watch.py 后台静默增量同步，不消耗前台任何算力与焦点。
  • 禁空脑断言铁律 (R1)：模型在声称「我上次怎么做 / 历史配置是这样」前，必须调用 ag_archive.py 检索客观历史记录。
实战战果：存有跨 3 个月数万条真实交互，让模型无法凭幻觉编造历史。
System 03 · 协同防污染
TwinBridge & AI 责任审计
核心目标：多脑协作分工、杜绝上下文交叉污染、代码责任到模型。
将 Antigravity（全局架构/调度）、Claude Code（深耕重构）与 Codex（垂直落地）融合，同时建立绝对防污染隔离机制。
  • 防污染隔离机制：全端通用铁律 (R1~R52) 跨端共享，而各 Agent 独有的 hook 超时与环境病灶严格隔离，互不传染。
  • .ai-audit 责任追溯链：ai_who_did_this.py 工具支持一键按文件追溯是哪个模型（gemini-2.5-pro / gpt-4o / sonnet）修改的。
  • 避免找错人骂：彻底告别“不知道谁改崩了代码”的多模型黑盒交接困境。
实战战果：实现 3 个异构平台无缝接力同一代码库，零上下文踩踏。
⚖️ 工业级深度对比：Frank 自研系统 vs GitHub 开源方案
为什么 GitHub 上的方案完全解决不了 Frank 实际面对的恶劣工程问题？
对比维度 GitHub / 业界所谓“大神”的同类方案 (SWE-bench / LangGraph / NeMo 等) Frank 本地自研三套治理体系 (Superego + Brain + TwinBridge)
1. 核心定位与运行形态 离线无菌室 测评/编排框架：如 SWE-bench、Inspect 是离线跑分题库，写学术论文用的；LangGraph/CrewAI 是玩具级链路编排。你在日常终端敲代码时，它们根本不在现场。 实时带电护栏 实时外审硬裁判：直接焊死在日常交互环境（Claude CLI / Antigravity / Codex）。模型生成每一行文字、调用每一个命令的瞬间，外挂网络毫秒级介入审查。
2. 拦截权威与硬度 软提示词劝导 绝大多数是用 System Prompt 劝模型“请认真写测试”、“请不要撒谎”。模型在长上下文下注意力衰减，说偷懒就偷懒，提示词毫无物理约束力。 物理硬断闸门 带电硬门禁：违例直接拒绝工具执行、强制掐断输出、直接在控制台喷出判定红标，模型不纠偏就无法推进下一步。
3. 视觉与交互真实交付 瞎子猜盲盒 开源 harness 绝大多数只验 exit code == 0 或返回了 200。页面哪怕排版崩溃、按钮被遮挡、红字报错连天，开源工具也认为“成功交付”。 Visual-Proof-Gate 必须亲眼看像素：强制启动无头浏览器真机渲染，抓取完整截图并调用图像工具读取像素点验。看不到截图绝不允许说“改好了”。
4. 记忆与教训复利 记忆玩具 开源的 Mem0 / MemGPT 只存几句“用户叫什么”、“喜欢 Python”的碎片。模型犯过的致命架构错误，新会话一开立刻再犯，没有任何教训进化链。 706 篇连续进化 血泪教训数据库：706 个经过 5 步 Postmortem 提炼的“错误形状”。模型只要敢触发类似形状，系统立刻唤醒历史教训当场抽打。
5. 多模型责任追溯 黑盒甩锅 开源方案通常绑定单一提供商（只管 OpenAI 或只管 Anthropic）。多模型切换时，代码改崩了根本无法查证责任人。 跨端归属与防污染 .ai-audit 追溯系统：一行命令 ai_who_did_this.py 查清每个文件是由哪个模型、哪个版本改动的，责任到人。

无菌室里的科研人员与战壕里的一线房东工程师，有着完全不同的生死诉求
❌ 学术界与开源网红大神的盲区：他们不背真实生产事故
GitHub 上所谓的大神，绝大部分是框架开发者、论文写作者或 Demo 演示者。他们的目标是跑一个贪吃蛇、写一个两百行的爬虫，或者在学术数据集上刷个 5% 的点数写论文。

他们不需要面对旅客半夜 12 点在吉隆坡大楼前被红字拦截进不去门、发怒差评的真实商业损失！他们没有经历过模型天天在几万行工程里“口头答应却不做”、“偷偷把功能改回三个月前旧版”的抓狂。
✅ Frank 的护城河：从真实痛感里长出来的工业安全结构
Frank 不是在象牙塔里推演理论，而是在每天十几小时的高强度结对开发中，被模型偷懒、甩锅、欺骗真实痛击了数百次。

这 706 篇教训、97 道闸门不是凭空设计出来的，而是每一次被坑之后，用「承认错误 ➔ 提取形状 ➔ 查发病次数 ➔ 机器防范 ➔ 落地代码」的硬核工程纪律铸就的防塌方钢结构。没有 600 小时的重度实战，任何人都写不出这套规则。
